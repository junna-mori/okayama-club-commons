# 次の担当者・AIへの引き継ぎ

このファイルとプロジェクト全体を渡すと、続きを編集できます。新規に作り直す必要はありません。

## 第2版の追加要望と対応

「岡山大学公式の雰囲気を出すが、公式とは名乗らない」「各部活動・飲食店に生成画像を実際に入れる」という要望に対応しました。ヘッダーを学生生活案内のような2段構成に変更し、濃紺の案内メニューと端正な文字組みを追加しています。独自の大学章や、大学の公式ロゴは使っていません。

`university.css` がデザイン変更を定義します。ホーム1点、部活動8点、食事5点の生成画像を同梱し、画像の近くにAI生成イメージと表示しています。料理画像は実際の提供メニューではありません。画像から食事対応や活動条件を推定しないでください。プロンプトは `IMAGE_PROMPTS.json`、画像一覧は `ASSETS.md` を参照してください。

単独HTMLの出力処理も画像全点の埋め込みに対応済みです。サイト・画像を変更したら `npm run export-preview` で作り直します。

## ユーザーの目的と合意済み事項

岡山大学の部活動に留学生が興味を持つ機会と、日本人学生側が受け入れを考えるきっかけをつくる。入部後の交流を支えるため、食文化の理解と一緒に食べられる場所も紹介する。

- 初期表示は英語。日本語・英語を切り替える。
- 見た目は落ち着いて読みやすい大学案内の雰囲気。
- 色は企画資料PPTXの濃紺 `#182053`・黄色 `#F4C44D` を踏襲。
- WIZARDS以外の部活動も掲載する。
- 津島周辺を中心に、公式情報を調べた飲食店候補を掲載してよい。
- 写真・個人名・体験談の本人名義の掲載は後で確認する。現在は写真や個人名を使わず、企画資料の体験を匿名の説明文として要約。
- 別の方のAIがGitHub・Vercel等に公開する想定。今回の制作では外部公開していない。

## できていること

ホーム、部活動一覧・詳細、食事候補・食文化、参加ガイド、背景・出典の画面を実装済み。PC・スマートフォン向けのレイアウト、日英検索、複数条件フィルター、部活動のブラウザ保存、日英の相談文作成・コピー、食事の例文コピーが動作する。相談文のコピー後は利用者自身が各団体の公式窓口で送信する。

部活動8団体：WIZARDS、写真部、茶道部、サイクリング部、吹奏楽団、弓道部、ECOLO、バドミントン部。

食事候補5件：Shah Arena、アオババ岡山大学店、マスカットカフェテリア、Plant-Based Cafe PEACH、SALT－石川食堂。

## 公開前に本人へ確認する内容

1. サイト名COMMONSを正式に採用するか。現状は制作上の仮称。
2. 運営者名・問い合わせ窓口・訂正依頼の連絡先。未確定のためダミーのメールや送信フォームは設けていない。
3. WIZARDSの公式Instagram等、見学相談を受ける窓口。現状は大学校友会の公式団体紹介へ案内。
4. 本人・部員の写真、WIZARDSのロゴ、個人名、体験談を本人名義で載せる場合の許可。元PPTXの写真やロゴは成果物に含めていない。
5. ほかの団体の掲載内容・現在の活動日・留学生参加条件・言語対応・見学方法。
6. 店舗の現在の営業、食事対応、予約方法、グループ対応。掲載は公開情報を読んだ段階で、店舗取材は未実施。
7. 大学の公式事業として扱うか、自主制作のままにするか。確認できるまで、公式サイトの表示や大学章を追加しない。

## データを増やすとき

`data.js` の構造に沿って追加する。団体は英語名を独自に翻訳した場合、そのことを維持して表示する。受け入れを確認せずに「留学生歓迎」「英語対応」「入部可能」と断定しない。

`beginner: true` は公式紹介に初心者歓迎・初心者が多い等の記載が確認できた場合のみ。`false` は初心者不可の意味ではなく、このフィルターの根拠を登録していないという意味。

飲食店の `diets` は `vegan` / `halal`。根拠がある場合だけ登録し、ページ上の注意文も具体的に維持する。空配列は未確認。現状の `halal` はShah Arenaの認証商品の販売・ケータリング紹介を示し、全料理の認証を意味しない。`vegan` も、店舗全体が完全菜食か、相談できる料理があるかを本文で区別する。

確認日 `reviewedAt` は実際に更新を確認した日だけ変更する。現在は全データを同日に調査したため共通の日付だが、運用時は各項目の `reviewedAt` へ拡張するとよい。

## 既知の制限

- 部活動の全団体を網羅していない。公式一覧へのリンクを併設。
- ライブの営業情報、地図の埋め込み、自動翻訳、申し込み送信、管理画面はない。
- 各ページはクライアント側で生成されるため、検索流入やページ別SNSプレビューを重視する段階では複数HTMLの事前生成を検討できる。今はレビュー用のため検索掲載を抑制。
- 外部サイト・ホスティングの利用規約やアクセス記録は、それぞれの運営者の方針による。
